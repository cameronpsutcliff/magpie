Magpie

A daily edition of what became possible in AI.

Purpose Architecture Operations Contracts Release Decisions Limits Handoff

Purpose & Data Scope

  • Magpie ranks public AI developments and publishes one Edition per Chicago calendar day.
  • The feed serves the website, Morning Brief and YouTube pipeline.
  • Inputs and published JSON are public. Credentials, local run logs and editor caches are operational data.

Architecture & Consumers

  • Upstream. GitHub, HN, Hugging Face, lab feeds, changelogs and public policy and advisory feeds.
  • Home integrations. The brief from magpie youtube and Grok live search over the curated X roster.
  • Consumers. Morning Brief and the YouTube pipeline read runner outputs. The feed powers cameronsutcliff.com/magpie.

Environments, Scale & Cost Controls

  • Local / acceptance. Run python3 -m magpie run --cloud --no-llm in a disposable checkout to inspect output. There is no dedicated UAT environment in this repo.
  • Production cloud. GitHub Actions runs at 11:10 and 13:10 UTC, with manual dispatch and a 40-minute job cap.
  • Production home. An always-on runner enriches the daily Edition and reviews source quality on Sundays.
  • Scale. About 35 public sources plus the X roster. The daily collector pool has eight workers and isolates failures.
  • Model spend. Each lane has a timeout. Try the next only after failure or rejection, and stop at the first accepted JSON.
  • Replay. --reuse-editor reuses saved editor and possibility outputs when available, avoiding repeat calls.
  • Cloud spend. The cloud uses Claude only when configured with a credential. Otherwise it runs with --no-llm.

Data Contracts, Auth & Dependencies

  • Consumer API. Versioned JSON files in Git. Readers need only the published files.
  • Edition and rollups. data/v1/days/<date>.json and data/v1/rollups/<date>.json use Chicago dates.
  • Projections. Latest, archive, feed, element and idea indexes, and constraint and threat registers live under data/v1/.
  • Stable links. Capabilities use /magpie/c/<date>-<id>. Possibilities use /magpie/i/<id>.
  • Validation. Published schemas define the versioned shapes. Invalid ideas indexes leave the last good file in place.
  • Cloud auth. Actions uses its repository token for Git writes and optional Claude OAuth or Anthropic API secrets.
  • Home auth. The launcher uses an explicit GitHub account, untracked .env.local and authenticated CLIs.
  • Portability. The keyless cloud path has zero personal-laptop dependencies. Home enrichment requires an explicitly provisioned host and tools.

SDLC Framework & Release Pipeline

  1. Specify and branch. Use the glossary and ADRs to scope the change. Open a feature-branch PR into main.
  2. Test. From the repo root, run python3 -m pytest -q. The editorial seam baseline is 301 tests.
  3. Review. Have a different model family challenge the diff, test evidence and consumer contract before merge.
  4. PR gate. ADR 0002 requires pytest on every PR. The current workflow runs editions on a schedule or manual dispatch.
  5. Promote. Merge reviewed code to main. Cloud and home commit Edition data through their respective launchers.
  6. Precedence. An edited home Edition supersedes a plain cloud Edition for the same day. --force overrides protection.
  7. Rollback. Use git revert <commit> on the faulty code or Edition commit. Verify the restored feed and page links.

Key Decisions & Stack Fit

  • ADR 0001 targets one publication seam for writes and repairs, with receipts, precedence and stable page IDs.
  • ADR 0002 names magpie-runner the operational checkout and requires schema tests and a PR test gate.
  • ADR 0003 targets a shared build seam and prior-only replay. The editorial JSON seam is implemented.
  • Stack fit. Python 3.12+ and its standard library handle batch collection, ranking and JSON. Thin launchers handle Git transport.

Known Limits & Active Debt

  • Repair and generator commands still write some projections outside the proposed publication seam.
  • Daily and backfill orchestration remain separate. ADR 0003 calls for a shared build and receipt.
  • Studio and Spark model adapters are planned. The editorial seam currently supports Claude and Codex.
  • The second checkout can drift. ADR 0002 calls for fast-forwarding or retiring it.

Domain Glossary & 10-Minute KT Entry Points

Edition
The dated publication for one Chicago day, from home, cloud or backfill.
Item
A normalized collector observation before grouping and selection.
Event
A ranked editorial record built from Items sharing a canonical key.
Canonical key
The stable identity used to group observations across editions.
Capability
A tool, model or development that changes what someone can build or do with AI.
Follow-up
An Event about what changed for a previously covered Capability.
Library
Earlier Capabilities available as partners for current arrivals.
Possibility
A proposed use of Capabilities with a recipe and a falsifiable test.
Ingredient
A Capability used in a Possibility. builds_on refers to an earlier Possibility.
Register
The cumulative record of constraints or threats, used for recent fallbacks.
